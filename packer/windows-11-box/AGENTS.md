# Руководство по репозиторию

## Принципы проекта

Проект должен оставаться максимально простым и прагматичным. Добавляйте только то, что необходимо для сборки работоспособного Vagrant box: автоматическую установку Windows, WinRM, VirtualBox Guest Additions, Sysprep и проверку результата. Не добавляйте debloat, косметические твики, преждевременные абстракции или параметры «на будущее».

Хорошая архитектура здесь означает короткий и очевидный поток сборки, слабую связанность шагов и предсказуемую структуру каталогов. Один файл должен решать одну понятную задачу. Прежде чем создавать новый скрипт или каталог, убедитесь, что существующая структура действительно не подходит. Предпочитайте прямое решение дополнительному уровню обёрток.

## Структура проекта

`windows11.pkr.hcl` задаёт автоматическую установку, порядок provisioner-ов и создание Vagrant box. В корне находятся только два сценария: `Build-Box.ps1` собирает образ, а `Test-Box.ps1` выполняет smoke-тест. В `scripts/` находятся шаги, выполняемые внутри гостевой Windows; в `answer-files/` — файлы unattended-установки; в `vagrant/` — шаблон конфигурации готового box.

Каталоги `output/`, `output-*`, `packer_cache/` и `.smoke-test/` содержат временные результаты и не являются исходным кодом.

## Сборка и проверка

- `./Build-Box.ps1` — инициализирует Packer и создаёт `output/windows11-25h2-pro-ru-virtualbox.box`; Packer проверяет ISO по SHA-256 из HCL.
- `./Build-Box.ps1 -Force` — повторно собирает существующий артефакт.
- `packer fmt -check .` — проверяет форматирование HCL.
- `./Test-Box.ps1` — загружает box через Vagrant, проверяет гостевую систему по WinRM и удаляет тестовую VM.

Требуются Packer 1.14+, Vagrant 2.4.9+, VirtualBox 7.2+ и ISO с контрольной суммой из конфигурации.

## Стиль кода

Используйте отступ в два пробела для PowerShell, HCL и Ruby. PowerShell-скрипты должны задавать `$ErrorActionPreference = "Stop"`, использовать имена Verb-Noun, camelCase для локальных переменных, PascalCase для параметров и `-LiteralPath` для известных путей. Имена гостевых скриптов оформляйте в lowercase kebab-case, например `scripts/prepare-sysprep.ps1`.

## Тестирование и изменения

Изменения provisioner-ов сопровождайте явными проверками в `scripts/verify.ps1`. Перед smoke-тестом выполняйте полную сборку. Коммиты называйте кратко и в повелительном наклонении, предпочтительно по Conventional Commits: `fix: preserve WinRM after sysprep`. В pull request опишите изменение поведения, выполненные проверки и связанный issue.

Не добавляйте в Git ISO, собранные box-файлы, кеши или секреты. Учётная запись `vagrant`/`vagrant` и незашифрованный WinRM допустимы только в доверенной локальной среде.
