# Проверка аудита

## Исправлено

| Дефект | Исправление |
| --- | --- |
| Создание answer ISO ломалось между Windows PowerShell 5.1 и PowerShell 7 | Удалён несовместимый `Marshal.QueryInterface`; ISO проверен в обеих версиях PowerShell. |
| WinRM-команда в XML была длинной и дублировала `enable-winrm.ps1` | `FirstLogonCommands` содержит только поиск и запуск скрипта с answer ISO; генератор кладёт скрипт в корень ISO. |
| Guest Additions не находились по метке тома | Установщик ищется по файлу `VBoxWindowsAdditions.exe` на подключённых файловых дисках. |
| `VBoxService.exe` проверялся в неверном каталоге | Provisioner и verify используют фактический путь `%WINDIR%\System32\VBoxService.exe`. |
| Sysprep запускался до перезагрузки после установки Guest Additions | Добавлен `windows-restart`; verify требует запущенную `VBoxService`. |
| Прямой запуск Sysprep зависел от WinRM, который исчезал при очистке сети | Sysprep регистрируется как задача `SYSTEM`; WinRM только запускает задачу. |
| Восстановление WinRM блокировало `specialize` до готовности устройства | Команда перенесена в `oobeSystem/FirstLogonCommands`, после готовности пользовательской среды. |
| Reboot после Guest Additions превышал 15 минут | `restart_timeout` увеличен до 30 минут; обязательная проверочная перезагрузка сохранена. |
| Медленная Windows Setup превышала общий 45-минутный лимит WinRM | `winrm_timeout` увеличен до 60 минут; успешная сборка от этого не замедляется. |
| Packer отправлял клавишу до появления EFI-запроса загрузки с DVD | `boot_wait` увеличен с 5 до 10 секунд. |
| WinRM кратко становился доступен до завершения первой загрузки и обрывался с EOF | Добавлен официальный `pause_before_connecting = "5m"`. |
| OOBE зависал на обновлении или странице «Почему был перезапущен мой ПК?» | В обоих answer-файлах отключён интерактивный machine/user OOBE. |
| VM получила все 8 физических ядер хоста и отставала по виртуальному времени | Сборке и smoke VM выделены 4 vCPU и 16 ГБ RAM. |
| Архитектурный поток не содержал подготовку Sysprep | В поток добавлены answer ISO и prepare Sysprep. |
| `verify.ps1` не проверял локаль и Sysprep answer file | Добавлены проверки `ru-RU` и `SysprepUnattend.xml`. |
| `Test-Path` нарушал соглашение проекта | Для известного пути используется `-LiteralPath`. |

## Отклонено

| Гипотеза | Причина |
| --- | --- |
| Объединить verify и smoke-проверки | Они проверяют разные состояния: до и после Sysprep. Пересечение является проверкой сохранения контракта. |
| Проверять в тестах порядок каждого provisioner-а, README-путь и SATA-порт | Текущая конфигурация согласована; тесты не должны повторять все детали реализации. |
| Проверять индекс редакции ISO до установки | ISO закреплён URL и SHA-256; дополнительная проверка потребует лишнего инструмента и продублирует гостевую проверку. |
| Удалять диагностические файлы из `build/` | `build/` предназначен для игнорируемых временных результатов и не входит в VCS. |
| Добавить `variables.pkr.hcl` или подпапки гостевых скриптов | Проект собирает один фиксированный box; новые уровни не устраняют существующую сложность. |
| Удалить защитный шаблон `*.box` из `.gitignore` | Он предотвращает добавление box вне `output/`. |

## Проверка

- `New-AnswerIso.ps1` выполнен в Windows PowerShell 5.1 и PowerShell 7.
- `Test-Project.ps1` выполнен в Windows PowerShell 5.1.
- Полная сборка и smoke-тест требуются после изменения гостевой проверки.
