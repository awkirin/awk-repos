# Рабочий процесс

## Анализ

1. Сверить задачу с ТЗ и архитектурой.
2. Проверить фактическое состояние затрагиваемых файлов.

## Масштаб

- Локальное изменение с одним результатом выполнять напрямую.
- Несколько независимых результатов, изменение структуры или потока сборки
  разбивать на шаги с отдельной проверкой каждого.
- Не декомпозировать механическое изменение путей или один локальный фикс.

## Реализация

1. Внести минимальное достаточное изменение.
2. Не выходить за границы ТЗ.
3. Обновить связанные тесты и документацию.

## Проверка

- Всегда выполнять `.\tests\Test-Project.ps1`.
- После изменения `image/` или потока сборки выполнять
  `.\tools\Build-Box.ps1 -Force`, затем `.\tests\Test-Box.ps1`.
- Сборку VM запускать с видимым окном VirtualBox и визуально контролировать до
  завершения. Headless-режим использовать только по явному запросу.
- После изменения документации или структуры выполнять `git diff --check`.
- Диагностические снимки сохранять в `build/diagnostics/` с локальным временем
  в имени: `yyyyMMdd-HHmmss-description.png`. Перед анализом сверять время
  файла и идентификатор текущей VM; снимки прошлых прогонов не использовать.
- Невыполненную проверку явно указать с причиной.

## Завершение

Сверить результат с ТЗ и сообщить изменённые области и выполненные проверки.
